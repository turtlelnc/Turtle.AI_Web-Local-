# Agent Note：基于证据的 Agent 调研与 Team 角色

状态：已实现

[English](2026-09-16-evidence-based-agent-research-and-team-roles.md) | 中文

## 问题

既有 Codex 与 Flash-first 行为鼓励自主推进、产品发现和选择性升级高能力模型，但没有定义完整的可观察恢复策略。它仍可能在检查前提问、把任意既有失败当作理由、假定包管理器或运行时，或者在没有与风险相称证据的情况下宣称完成。产品调研也缺少明确的证据分类，以及继续、缩小、转向或停止标准。通用持久 teammate 要求 Lead 在每次委派时重新编写 Explorer、Builder 与 Reviewer 职责。

## 决策

内置 Prompt Profile revision `builtin-2` 为 `codex` 与 `flash-first` 加入共享的可观察工作策略。该策略要求提问前先检查、在范围内自主执行可逆工作、选择与仓库兼容的命令、保留无关改动、分类基线失败、遵循有界错误恢复阶梯、修复回归、执行与风险相称的验证并简洁交付。它区分已验证事实、用户明示约束、推断、假设与未知，并禁止编造用量、成本、时间、兼容性和测试结论。

Flash-first 还规定，只在调研能降低影响决策的不确定性时调研陌生产品工作。它检查请求、仓库、既有行为、工作流、替代方案和约束；研究竞品模式背后的问题与权衡，而不是照搬；并在主要风险具有验证计划后推进一个小型可逆里程碑。遇到已证明的不可能、冲突要求、不可用的关键依赖、被证据否定的价值，或权限／预算耗尽时，它会缩小范围、转向或停止。用户已经授权安全实现后，它不会要求重复批准。

Prompt Profile registry 保留 `builtin-1` 定义，以便精确解析手动会话选择，而目录与 Auto 模式公开 `builtin-2`。Profile 定义可以记录 `baseRevision`；缺少该字段的旧持久化 Custom Profile 按 `builtin-1` 解析，新创建的 revision 则捕获 `builtin-2`。这样可防止已记录的 Profile revision 悄悄获得不同的基础提示词。

实验性 `spawn_teammate` 工具接受可选的 `explorer`、`builder` 或 `reviewer` 角色。适配器会在委派任务前加入稳定角色约定。Explorer 收集带来源的证据且不编辑，Builder 负责一个实现范围及其聚焦验证，Reviewer 独立报告按优先级排序的发现且不编辑。这些是提示词层角色，不是文件系统或进程安全边界。专用 `spawn_user_tester` 仍是中立首次用户路径，可选模型的一次性 subagent 仍是高能力专家路径。

## 考虑过的替代方案

**逐字复制外部调研回答。** 其中关于 Windows 7、Python、UI 框架、市场和架构的示例未经验证，也不描述本仓库。固定调研百分比、任意的未回答问题阈值和强制批准还会导致不必要的停顿。因此只保留可观察的证据与决策框架。

**在 `builtin-1` 下修改既有内置提示词。** 这样 request header 和手动选择会声称使用相同不可变 revision，却产生不同行为。历史内置定义与捕获的基线 revision 会保留已记录选择的含义。

**在 Team 领域中强制执行角色。** teammate 共享同一工作区与工具面时，文本角色无法保证 Explorer 与 Reviewer 的只读行为。工具和文档明确说明该限制，把技术 confinement 留给沙箱化 Provider。

**在 Agent Loop 内构建自动重试与模型路由。** 融合架构保留 Harness Loop。本次变更定义可观察策略并复用既有可选模型 subagent 白名单；确定性传输重试仍由 Provider 与运行时接缝负责。

## 后果

默认 Codex 体验与可选 Flash-first 协调器现在共享更清晰的自主性、恢复、证据和完成行为，同时不改变 Provider、工具、权限、会话或 Agent Loop。产品调研可以在不再改变决策时停止，而不是消耗固定比例预算。Team Lead 能以更少的重复提示创建可重复的功能角色，同时用户不会被误导而把这些角色视作沙箱。更丰富的提示词会增加稳定前缀 token，选择 `builtin-2` 会按预期开始新的请求系列。聚焦测试覆盖未变化的通用委派和带角色前缀的委派；生成目录会公开新的可选字段。
