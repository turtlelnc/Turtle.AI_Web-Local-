# Agent Note: 构建期产品品牌配置

Status: implemented

[English](2026-09-09-build-time-product-branding.md) | 中文

## 问题

浏览器外壳分别固定了本地构建标签、空对话欢迎词、favicon、Web 应用清单和桌面安装包身份。下游发布者必须编辑多个互不关联的源码文件，才能呈现一致的产品身份；没有选择 profile 的本地构建还会显示 `DSH 本地构建`，即使产品仍然是 DeepSeek Harness。

## 决策

选择或不选择 profile 的构建都默认使用 DeepSeek Harness 客户端身份。三个公开构建变量提供覆盖整个渲染端的统一配置：`DSH_CLIENT_TITLE` 设置文档、侧栏和 Web 应用标题；`DSH_CLIENT_ICON_URL` 设置文档、侧栏、空对话和 Web 应用标志；`DSH_CLIENT_WELCOME_TEXT` 设置空对话欢迎词。空值保留内置名称、鱼形标志和由 locale 管理的欢迎词。

官方客户端构建 profile 除固定构建元数据外，只接受这三个明确的品牌覆盖值。完整客户端构建记录会捕获它们的准确值，因此发布打包流程能够验证自己消费的是同一套品牌产物。该 profile 仍然排除其他继承的 `DSH_CLIENT_*` 值。

Electron 打包通过 `DSH_DESKTOP_PRODUCT_NAME` 和 `DSH_DESKTOP_ICON` 读取原生安装包元数据。这两个字段不会改变渲染端；两个层面需要相同身份时，发布者需要在同一打包环境中设置客户端变量。

## 考虑过的替代方案

**把品牌存入用户设置。** 运行时设置可以改变渲染后的文字，却无法一致地改变初始 HTML、安装清单、可执行文件元数据或已签名应用图标。它还会让同一安装产物对不同用户呈现不同的发布者身份。

**要求直接修改源码。** 编辑每个消费方可以保持构建系统更小，但容易形成不一致的局部品牌替换，也会增加合并上游更新的难度。

**替换 slot 系统。** 侧栏和空对话 slot 对插件自有呈现仍然有价值。构建变量只提供部署默认值，不引入第二套运行时组合机制。

## 影响

品牌变更需要重新构建客户端；原生元数据变更还需要生成新的已签名桌面安装包。每个 `DSH_CLIENT_*` 值都是公开构建产物内容，不能包含秘密。自定义图片 URL 必须能够从已部署应用中解析，桌面图标输入必须使用目标平台要求的格式。
